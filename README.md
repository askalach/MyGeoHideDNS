# MyGeoHideDNS

Курированный hosts-файл для [DnsConf](https://github.com/askalach/DnsConf) — только те
сервисы, которые мне нужны, без остального содержимого upstream-списка.

`hosts/hosts` собирается скриптом и **не редактируется руками**.

## Что внутри

**Redirect** (строки `IP домен`) — категории из
[GeoHideDNS](https://github.com/Internet-Helper/GeoHideDNS):

ChatGPT (OpenAI) · Claude · Google AI · Grok · Meta AI · DeepL · ElevenLabs ·
Microsoft (Copilot, Designer, Xbox) · Notion

**Block** (строки `0.0.0.0 домен`) — трекерные списки HaGeZi (Apple, Samsung, Xiaomi,
OPPO/Realme, Vivo, Windows/Office) из реестра AdGuard.

## Как обновляется

Workflow `update-hosts` запускается ежедневно в 01:00 UTC — за полчаса до DnsConf
(01:30 UTC), чтобы тот забирал уже свежий список. Коммит создаётся, только если
изменилось содержимое: смены одной лишь даты сборки недостаточно.

Вручную: вкладка _Actions_ → **Update hosts** → _Run workflow_.

Локально:

    python3 scripts/generate_hosts.py

## Как менять набор сервисов

Список `KEEP_CATEGORIES` в `scripts/generate_hosts.py`. Названия должны совпадать с
заголовками секций в upstream **дословно** — если upstream переименует секцию, скрипт
упадёт и покажет актуальный перечень доступных категорий. Это намеренно: молча
потерять категорию хуже, чем упасть.

После изменения набора список в NextDNS нужно почистить — см. ниже.

### Ручные дополнения

Список `EXTRA_DOMAINS` в том же скрипте — для доменов, которых в upstream нет, но без
них сервис работает неполноценно. IP им подставляются те же, что upstream использует
для прокси, поэтому при смене прокси эти записи переезжают вместе с остальными.

Сейчас там `oaiusercontent.com`: вложения и сгенерированные картинки ChatGPT отдаёт с
хостов `sdmntpr<регион>.oaiusercontent.com`, а upstream перечисляет всего четыре
региона — при попадании на любой другой файлы не прикрепляются.

### Защита от обрезанного списка

Если новый файл содержит меньше 70% redirect-доменов от предыдущего, скрипт
останавливается — обычно это значит, что upstream переехал или сломался. Если
сокращение ожидаемое (сам убрал категории), запусти с `--force`.

## Очистка NextDNS

DnsConf добавляет rewrites, но **никогда не удаляет лишние**. В
`NextDnsRewriteService.cleanupOutdated` домен, которого нет в новом списке, просто
выбрасывается из очереди на добавление, а запись в профиле остаётся навсегда. Поэтому
сокращения hosts-файла недостаточно: удалённые сервисы продолжают ходить через прокси,
пока их не убрать через API.

    export NEXTDNS_API_KEY=...      # my.nextdns.io/account
    export NEXTDNS_PROFILE_ID=...   # ID из секции Endpoints
    python3 scripts/cleanup_nextdns.py           # показать, что удалилось бы
    python3 scripts/cleanup_nextdns.py --apply   # удалить

Скрипт трогает только `/rewrites`. Денилист не затрагивается — в нём могут быть записи,
добавленные вручную через интерфейс NextDNS.

Штатный способ из README DnsConf (прогнать workflow с пустыми `BLOCK` и `REDIRECT`)
здесь не подходит: он вызывает `removeAll()` и для денилиста тоже.

## Известные особенности

**`api.nextdns.io` стоит за Cloudflare и блокирует User-Agent по умолчанию.** Запрос с
`Python-urllib/*` получает 403 с телом `error code: 1010`, что снаружи выглядит как
отказ в авторизации и уводит диагностику не туда. Поэтому скрипты всегда выставляют
свой User-Agent. Настоящий отказ NextDNS выглядит иначе:
`{"errors":[{"code":"authRequired"}]}`.


**Rewrites в NextDNS всегда действуют на поддомены.** Отключить это нельзя, поэтому
апекс покрывает всё поддерево разом — так одна запись `oaiusercontent.com` заменяет
перечисление всех региональных хостов.

Из этого следует, что для NextDNS список во многом избыточен: `chatgpt.com` уже
покрывает все `*.chatgpt.com`. Схлопывание сократило бы ежедневную синхронизацию с
~4 минут до секунд. Но делать это огулом нельзя: в секции Google AI перечислены
`apis.google.com`, `suggestqueries.google.com`, `people-pa.clients6.google.com` — свести
их к `google.com` означало бы завернуть на прокси вообще весь Google. Схлопывать можно
только там, где апекс принадлежит одному сервису целиком.

**Второй IP не используется.** Upstream указывает каждый домен дважды, на два адреса
прокси. `NextDnsRewriteService.buildNewRewrites` применяет `putIfAbsent`, поэтому
срабатывает только первый — резервирования нет. Вторые строки сохранены как есть, чтобы
файл оставался совместим с upstream и с Cloudflare-режимом DnsConf.

**Денилист тоже накапливает мусор.** Та же аддитивная логика: домены, выпавшие из
списков HaGeZi, остаются в NextDNS. На момент перехода таких было около 90. Чистится
только вручную через интерфейс — автоматике мешает то, что отличить их от
самостоятельно добавленных записей нельзя.
